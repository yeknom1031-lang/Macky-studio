# わちゃわちゃタウン 全24ステージ画像制作計画

2026年10月4日改訂版。対象は、全24ステージを揃える初回完成版の画像・アニメーション制作。生成費用に上限を設けず、見分けやすい人物、背景に接地した動作、生活が続く街を優先する。この文書は設計時の制作仕様であり、すべての細部が実装済みという意味ではない。拡張版の実装を進めており、現在の原画数・収録内容・検証結果は[実装状況](IMPLEMENTATION_STATUS.md)を参照する。既存素材を再利用しつつ、追加原画も多数制作する。

新しい写真ルールは「開始時0回、カメラマンを1人見つけると1回獲得」。ステージ内のカメラマンは最大5人。同じ人からは1回だけ獲得できるため、1ゲームの獲得上限は5回とする。以前の初期3回・合計3枚というルールを置き換える。

## 1 制作範囲と数え方

**ブラウザ版の既存原画を活かし、これまでのコマ分け・コマ数で新しいベースを増やす。** 現行の追加シートは1行1体、歩行4コマ＋専用動作4コマ、10体を1枚にまとめる形式を基本としている。これを新規制作の出発点にする。全員に8方向の原画や3動作×12コマを用意する旧案を取り下げる。

| 項目 | 制作仕様 |

| 役割と動作 | 全体で250種類。行動仕様の種類であり、全員へ250クリップを生成しない |
| 既存素材 | ベース250種類＝人物232＋動物18。原本29シートと既存コマを保存し再利用 |

共通1,900人・人物合計4,300人は本計画の拡張案で、ユーザー指定の最終総数とは区別する。各ステージには専用100人と場所に合う共通住民を選ぶ。既存の顔・体格・服を新しい台帳の人物案へ置き換えて作り直さず、生成済みの固定IDを優先して割り当てる。

現物確認は[ブラウザ版の既存素材一覧](EXISTING_FORMAT.md)、新しい計算は[生成回数の試算](GENERATION_ESTIMATE.md)に記載。専用2,400人の基本シートは10人／枚なら240枚分。人物4,300人まで増やす拡張案では、既存232人を差し引き基本407枚分。役割ごとの追加差分、背景・環境、修正は別計上であり、この数字をゲーム全体の生成回数とはしない。

## 2 カメラマンを探して写真を獲得する

標準配置は各ステージ5人とする。5人とも専用100人の内数で、開始時の人数に含める。難易度設定で人数を減らす場合も上限5人。同じカメラマンを再度クリックしても獲得できず、再挑戦時だけ獲得状態を初期化する。

1. プレイヤーは撮影回数0で開始する。カメラ機能は残数0と分かる小さな表示にする。
2. 街でカメラマンを見つけてクリックすると、撮影回数が1増える。カメラマンへの正しいクリックはお手つきにしない。
3. カメラマンが顔を上げ、フィルム券を取り出し、差し出す短い動作をする。吹き出しは出さない。取得済みはバッグを閉じるなどで示すが、カメラ自体は消さない。
4. 写真の枠は画面面積の約10％。ドラッグして位置を固定し、撮影操作で1回分を消費する。空振り写真も消費する。キャンセルは消費しない。
5. 撮影からゲーム内時間で3秒後に写真を見られる。写真には撮影時点の背景と捜索対象だけを残す。他の人物・動物は透明にする。前景や乗り物に隠れていた対象も、写真の中だけは姿を確認できる合成にする。
6. 範囲に対象がいなければ背景だけの写真になる。写真をクリックしてもクリアしない。写真を閉じて現在の街から探す。
7. 撮影・現像・写真閲覧中も街と制限時間は進む。対戦相手を写真で停止させない。一時停止またはコントローラー切断時は両者・時計・現像を一緒に停止する。

保持回数は獲得数−使用数、累計獲得は最大5。例：2人発見→2回、1枚撮影→1回、別の1人発見→2回。同時現像は1枚まで。写真履歴はそのゲーム内で最大5枚。カメラマンは捜索対象や2人目の操作キャラクターには選ばない。

カメラマン120人には、共通の機能を伝える「カメラ＋フィルム券入れ」を持たせる。顔、体格、衣装の形、機材の種類をステージごとに描き分ける。一般住民で写真趣味の人がいる場合は、券入れを持たせず、獲得対象との違いを小さな表示サイズでも読めるようにする。未発見のカメラマンに光柱・常時輪郭線・矢印は付けない。

必須素材は、人物120人の通常セットに加え、券を取り出す・渡す・取得後に戻る動作、券の表裏、カメラ機能の0〜5回表示用の共通絵、獲得時の小さな光、現像中と現像完了の装飾。数字、ボタン枠、撮影枠は文字と図形で正確に描画し、画像生成で焼き込まない。

## 3 全24ステージを揃える工程

制作は小さな検証単位に分けるが、完成範囲は最初から24ステージで固定する。最初の7ステージだけを完成版として出す計画にはしない。大規模生成の前に接地・動作・描画負荷を確認して、24ステージ分を同じ誤りで作り直すことを防ぐ。

| 工程 | 作るもの | 次へ進む条件 |
| --- | --- | --- |
| A 全体設計 | 24マップの構図、全キャスト枠、250役割、各場所の床と遮蔽ルール | 必要な人数、建物、乗り物、カメラマンの配置可能数が成立 |
| B 共通画風の確定 | 既存原画を基準に、新規の店頭・2階・乗降のサンプルと必要な差分 | 既存のコマ構成・絵柄・縮尺との一致、少ないコマでの動作の読み取りを確認 |
| C 全24ステージの設計画 | 既存7背景＋新規17テーマ、分割・前後関係・100人ずつの配役表 | 専用人物が場所と行動を持ち、カメラマンを5人配置可能 |
| D 本制作 | 既存素材＋新規ベース、背景の拡張、乗り物、小物、環境と役割差分 | 台帳の各枠を再利用・追加・補修で充足。全枠に新しい画像生成を課さない |
| E 背景との組み合わせ | 250役割の接触位置、2階、階段、相手との受け渡し、乗降 | 通り抜け・浮遊・手の不一致を解消。3秒以上隠れ続けない |
| F 全24ステージの実機確認 | 最小500人、最大2,000人、写真、2人対戦、コントローラー | 全ステージで180秒間の遊びと長時間放置を確認して初回版完成 |

生成候補・修正版・不採用は保存する。上限予算を使い切ることを目的にせず、合格しない箇所を何度でも直す。費用上限がなくても、キャラクター同一性の確認、道具との接触調整、性能確認は省略できない。

## 4 背景と人物を一つのセットにする

画面は斜め上から見る2D絵本調を基本とする。建物の正面が読め、2階の窓にも人が見える角度を画風基準画で決め、全素材へ適用する。背景に人を描き込まない。静止画の人と動く人が混ざる状態を作らない。

各マップは既存背景を活用し、必要箇所を地面・水面、建物奥、1階の床、2階の床、人物、カウンターや手すり、屋根や近景、環境効果に分ける。物理的な前後関係に従って描画順を決める。正面窓だけの貼り絵を2階の歩行領域として扱わない。

| セット | 人物と動作 | セットとして必要な絵 | 接地と遮蔽の確認 |
| --- | --- | --- | --- |
| 店頭 | 店員が包み、客が受け取り、支払い、離れる | カウンター奥と手前、作業台、商品各状態、袋、両者の手 | 足は床、手は商品へ。商品が二重に残らない |
| 2階の窓 | 窓を開ける、水をやる、鉢を戻す | 窓枠前後、床、壁、開閉窓、鉢、じょうろ、水 | 窓枠の手前と奥を分離。階段から到達できる |
| 会話 | 向き直る、身振り、相づち、別れる | 2人以上の個別ポーズ、必要なら椅子や机 | 視線と手を相手へ向け、顔が互いに隠れ続けない |
| 釣り | 餌を付ける、投げる、待つ、引く、魚を外す | 竿、リール、糸、浮き、水紋、魚、バケツ | 竿先と糸、手と柄を合わせ、魚を瞬間移動させない |
| 乗り物 | 待つ、乗る、座る、揺れる、降りる | 車体奥と手前、扉、座席、安全バー、車輪、乗降ポーズ | 乗客が窓や車体を貫通しない。乗車中も見分けられる |
| 警察と泥棒 | 発見、追跡、曲がる、袋を落とす、回収 | 走りと停止、振り向き、袋の保持と落下、警察の合図 | 探索対象も通常住民も同じ歩ける領域に従う |
| カメラマン | 構える、撮る、見直す、券を渡す | カメラ、三脚、券入れ、券、手の差分 | カメラで顔全体を3秒以上隠さない |

各セットには、床の高さ、立ち位置、手の接触点、座る位置、入口、出口、定員、立入禁止領域、前後の画像、相手側の動作、途中中断時の戻り方を記録する。これらの数値・当たり判定・移動経路は生成画像から自動的に正しく得られるものではなく、制作時に指定して検証する。

背景の基本枠は、各ステージ6枚の設計画、面積に応じた地面区画、8か所以上の代表建物、12か所以上の生活地点、48点以上の小物、4種類の乗り物、8種類の環境セット、6本のイベント。後半は区画・建物・生活地点・小物を増やす。詳細数量は台帳に示す。これらは配置・検品の枠であり、各枠を別画像として新規生成する数ではない。既存素材と同じ部材を使える場所は共用する。

## 5 人物の外見と多様性

小さく表示したときにも、輪郭、髪や帽子、服の形、持ち物、姿勢から少なくとも3つの違いが分かる人物を作る。色は補助情報にする。顔だけの差、柄だけの差、同じ素体の単純な着せ替えは別デザインの合格条件にしない。

年齢、身長、体格、肌、髪質、性別表現、障害の有無、暮らし方を職業と独立して分散する。おじいちゃん・おばあちゃんにも職人、演奏者、研究者、遊ぶ人を用意する。美形、ぽっちゃり、大柄、小柄、細身、筋肉質などを同じ評価基準で魅力的に描く。ピエロは複数の顔立ち・衣装構造・芸を持たせる。

LGBTQ+の人物も日常の働き手、学生、家族、観客として配役する。性的指向や性自認は外見から推測する要素にせず、設定や関係性として持たせる。全員に虹色の服を着せるような記号化はしない。車いすや杖などは道具と動きの整合を取る。子どもには危険な作業や職業を割り当てない。

台帳の人物説明は初回の制作指示であり、完成画像の存在を示すものではない。複数人に共通する体格語があっても原画・顔・衣装は別に描き、シルエット一覧で重複を審査する。共通住民1,900人についても、190種類の色違いなどへの置換は認めない。

新規1体の基本は歩行4コマ＋主要動作4コマ。元シート、キャラクターID、行と列、切り出し範囲、動作の対応を納品する。見本ポートレートは採用済みの原画を使い、全員分の設定画・8方向・分割パーツを別発注しない。

台帳の主要役割と補助行動は、その人物が街で何をするかの候補であり、3本の独立した生成クリップを必須にする意味ではない。手を振る、身振りする、立ち止まるなどは既存ポーズと再生タイミングで成立するか確認し、足りない場合だけ差分を作る。カメラマンの券の受け渡し、釣りの投げ込み、乗降など絵が必要な部分は省略しない。

## 6 現行のコマ構成で自然な生活を増やす

現行の追加170種類は、歩行4コマ＋専用動作4コマを基本に17シートへ収めている。フェンシング1体は専用動作3コマ。ゲームでは歩行5枠・ジェスチャー5枠・専用動作5枠の15再生枠へ割り当てる。15枠すべてに別の新規原画があるという意味ではない。

初期16種類と旧64種類の異なるコマ数も維持し、一律8コマへ減らさない。生成した画像の実際の区切りを確認し、キャラクターごとのコマ数をメタデータで扱う。1シート10体は基本値で、大きな道具や複雑な動きは5体程度に減らす、必要な列を足す、追加シートを作るなどで調整する。

| 対象 | 基本の扱い | 追加生成する場合 |
| --- | --- | --- |
| 新しい住民 | 歩行4＋主要動作4を基本に新規生成 | 足元や道具の動きが読めない箇所 |
| 既存住民 | 現在の顔・体格・衣装とコマを再利用 | 新しい仕事、座席、手の受け渡しに不足するポーズ |
| 会話や休憩 | 向き・速度・停止・既存の身振りを調整 | 椅子に座る姿など、元の絵で成立しない状態 |
| 店員・釣り・乗降 | その役割の主要4コマを選ぶ | 準備、受け渡し、乗り降りなど不足する状態 |
| カメラマン | 撮影する姿と既存の待機を活用 | 券を出す・渡す・戻す差分 |
| 鳥・風船・雲 | 絵を生成し、位置と揺れは制御する | 羽の切替、着地、糸の変形など必要な差分 |

追加のコマ数を全員へ掛け算しない。役割・人物・設備ごとに「既存で使える絵」「不足する絵」「ゲーム側の制御で対応するもの」を記録してから発注する。20種類の移動タイプも、まず歩幅・速度・停止・補助具に応じた再生設定として扱い、20×6区間×8方向の原画生成は必須にしない。

250役割は、開始・継続・終了・中断・再開・相手との同期を設計する。絵コンテは既存ポーズの並べ替えやラフでも作れ、250回の独立した画像生成を自動的に要するものではない。同じ周期で全員が動く状態は避ける。

初期の行動比率案は移動30％、仕事30％、会話や遊び20％、休憩15％、乗車5％。人物ごとの速度や用事、設備の定員と近くの空き具合で動かし、用事の切れ目に空いた経路を選ぶ。会話の切替や行ったり来たりを、全て新しいコマで表現する必要はない。

重なりが3秒に達する前に、周囲が歩幅を緩める、横へよける、席をずらすなどで解消する。2人対戦で操作している人を勝手に移動させない。通路の進入制御と設備の定員も調整する。建物による遮蔽は窓、屋根、前景の切り欠きで別に解決する。

## 7 動物と環境も原画から作る

犬8、猫8、鳥24、陸上小動物16、水辺の生き物16、昆虫8、大型動物8、空想動物8で合計96デザインを提案する。種や体形・顔・耳・尾・羽の構造で描き分け、単なる毛色違いを数えない。個体として登場する同一外見の動物も同じ場面へ複数出さない。魚群や昆虫の群れは複数の異なる個体を含むひとつの群れ素材として設計する。

既存の動物18種類のコマを再利用し、新しい動物も現行の構成を基本に作る。静止、移動、食事、毛づくろい、遊び、着地などは必要な行動候補であり、全96種へ6本ずつを必須にしない。鳥は羽ばたき・滑空・着地など、実際の役割に足りない絵だけを追加する。

風船は球形だけでなく、動物形、星形、魚形、雲形などの輪郭を作る。浮いて揺れる、糸が遅れて曲がる、持ち主の手に引かれる、放れて上昇する状態を分ける。糸の根元が手から外れないようにする。飾りの風船と放れて飛ぶ風船は別のイベント状態にする。

雲は遠景・中景・薄い雲・低い霧を原画として作り、ゆっくりした移動や変形は制御で行う。雲を1コマずつ生成する必要はない。水面、反射、旗、木の葉、湯気、雪、花びら、灯り、紙吹雪にも原画を用意する。原画を作る部分と移動・揺れを制御する部分を台帳で分ける。

環境アニメーションが捜索の邪魔になる楽しさは残しつつ、対象を長時間覆う大きな鳥や風船の通過は避ける。対象の顔が読めなくなる閃光、点滅、過度の煙は不合格にする。環境だけを軽くする設定を用意しても、人物数や見分けるための解像度は維持する。

## 8 2人対戦に必要な素材

探す側はマウスで地図移動・拡大・カメラマン発見・撮影を行う。隠れる側はSwitch互換コントローラーのスティックで対象を動かし、近くの設備で自然な行動に参加する。ボタンで座る、買う、釣るなどを選べるようにし、場所にない動作はできない。外見変更は行わない。

対象もNPCも同じ絵とアニメーションを使う。操作対象にだけ専用の枠、足元マーカー、強い影を付けない。走る、急停止、方向転換、座る、行動へ入る・出る、相手を見て反応する動作を確認する。クリックで見つかった、時間切れで逃げ切った、お手つきの演出は全画面に対応する。

同じ画面の対戦は1画面程度の会場で成立させる。巨大マップは、探す側のカメラが移動すると隠れる側が自分を見失うため、隠れる側専用の別画面を使う案を維持する。追加画面がないときはステージ内の区画を対戦会場にする案。巨大マップ全域の2人対戦を1画面のまま保証する仕様にはしない。端末構成と操作感は試作で決め、背景全体の制作は先に進められる。

コントローラーの接続、ボタン配置、スティックの遊び、切断後の再接続を実機確認する。Switch互換という名称だけでMac対応を保証しない。接続画面の本体絵とボタン位置の例は用意するが、割り当てたボタン名は文字で表示する。

## 9 再利用と追加生成の一式

| 区分 | 再利用するもの | 追加生成するもの |
| --- | --- | --- |
| 画風と設計 | 既存原画、既存ポーズの合成、移動や接点の資料 | 新しい表現を決めるのに必要なサンプルのみ |
| 背景 | 既存7ステージの絵と使える部材 | 新17テーマ、後半の拡張部分、切り出しだけでは足りない前景 |
| 建物と生活拠点 | 同じ用途・縮尺の床、窓、机、道具 | 2階・カウンター・座席など背景に合う不足部材 |
| 人物 | 既存232人の元の外見とコマ | ステージ専用2,400人と、採用する共通枠の不足分 |
| 役割 | 使える専用動作、ジェスチャー、歩行 | その人物と設備に必要な追加差分 |
| 動物 | 既存18種の原画と動き | 既存にない生き物、必要な飛行・着地など |
| 乗り物 | 既存小物の使える車体・道具 | ステージ固有の乗り物、前後部材、扉、座席、可動部 |
| 環境 | 同じ形で使える小物・生物の原画 | 雲、風船、鳥、波、湯気など未制作の原画と必要な差分 |
| イベント | 既存人物・設備とゲーム側の同期 | その場面で不足する絵と効果 |
| 写真と画面 | 人物見本、背景からのステージ表紙、文字と枠 | カメラマンの券、道具、獲得や現像の必要な装飾 |

台帳の地形754区画・建物302式・生活拠点754式・小物1,618枠は、組み合わせと配置を検証する単位。すべてを別々のAI生成画像として発注しない。96乗り物・192環境・144イベントも、既存画像の参照と追加画像を分けて見積もる。

旧案の「1人46点」「人物原画197,800点」「全員に3動作×12コマ」「全体1万〜2万回」は、今回の制作方針には適用しない。新しい基本シートの計算と未算定の追加分は[生成回数の試算](GENERATION_ESTIMATE.md)にまとめる。

## 10 画像の寸法と納品形式

現在のコマ分け、人物の縮尺、絵の密度を基準にする。既存の追加シートは1,122×1,402pxに10行×8列で、セルは概ね140px四方。全員の各コマを512px角に作り直す指定は外す。新規原画では輪郭と手元の読める品質を確認し、必要なら同じ構成で解像度を上げる、1枚に入れる人数を減らすなどで調整する。

既存ゲームは80pxの描画用セル、人物本体約60pxが目安。原本を維持し、切り出し・圧縮・表示側で改善できる範囲を先に確認する。拡大でぼやける素材を全員一律に再生成せず、問題のある素材を補修対象にする。

透過が必要な人物、動物、道具、前景、効果は透明背景で作り、白背景や市松模様を描き込ませない。足元基準、画像内の余白、向き、光の方向を固定する。背景の地面と人物の影は分離し、人物の姿勢に合う影を付ける。スプライトシートのコマは固定セル・同一基準点で組み直す。

納品セットは、元の透過シート、切り出し情報、動作の対応、必要な追加差分、再生確認用動画またはGIF、背景との接地確認画像、ゲーム用圧縮版。分割パーツは必要な素材だけに用意する。動画やGIFは検品用の書き出しであり、別の画像生成納品数には含めない。

メタデータには、素材ID、用途、ステージ、人物ID、役割ID、方向、動作、コマ、接地点、道具の接触点、表示順、原画参照、プロンプト、採用状態、修正履歴を記録する。進捗は「未生成→候補→原画合格→連続性合格→背景との組み合わせ合格→実機合格」で管理する。

ファイル例は S03 キャラクター028 釣り 動作開始 南東 01、S09 建物04 手前、S15 乗り物02 座席前面のように素材IDで統一する。実際の台帳には機械処理用のIDを付け、読者用の名前も保持する。

## 11 生成指示のテンプレート

各生成では「共通画風＋確定した参照画像＋今回の対象＋納品条件＋変更してはいけない特徴」を渡す。文字だけで毎回同じ人物を再現しようとしない。参照画像は採用済みの原画だけを使い、候補同士の特徴を混ぜない。

**新規ベースのシート**：1行に1体、前半4コマは歩行、後半4コマはその人物の主要動作。基本は10人を10行に描く。行をまたいで顔・服・道具が混ざらず、コマの間に切り出せる余白を取る。かわいい絵本調の斜め上から見たゲーム用人物。指定する年齢・体格・髪の輪郭・服の裁断・道具の3つ以上の特徴を固定する。頭から足先まで入り、透明背景、手足と道具が分離して読める。背景や文字や影の床を描かない。他キャラクターの配色替えにしない。通常表示64〜96pxで識別できる形にする。

**連続ポーズ**：参照人物と同じ顔、体格、服、道具を保ち、指定方向と同じカメラ角度で動作の指定時点を描く。足元基準、頭の大きさ、服の縫い目、道具の形を固定。今回は接触前・接触中・受け渡し後のどれかを明記し、相手側の手の位置を参照する。必要な絵を分割生成し、後工程で固定セルへ配置する。

**背景と生活拠点**：指定ステージの無人の場所。床、入口、カウンターの高さ、2階の床と階段、奥と手前を分離できる構造。人物を描き込まない。歩ける面を装飾で塞がない。参照人物の縮尺と光に合う。看板の文字は空欄とし後から追加する。

**環境素材**：指定する生物や風船などを同じ向き・光で描く。動く部分と固定部分を分離する。飛行、着地、糸の付け根、枝への接触など必要な状態を明記する。透明背景。光や煙で探索対象を覆わない輪郭と密度にする。

**補修**：元画像を参照して、問題の手、足、道具、輪郭など指定部分だけを直す。顔、衣装、構図、縮尺、既に合格した部分を維持する。全体を描き直して同一性を崩す場合は、元画像と比較して再審査する。

例：海辺のマルシェの釣り人は、まず桟橋の床と水面の高さを確定し、人物の待機原画を作る。次に竿の持ち手と釣り糸の接触図を作り、餌付け→投げる→待つ→引く→魚を外すの順にポーズを生成する。魚や浮きを含む全要素を背景に置き、手離れや瞬間移動がないことを確認する。

## 12 軽量化と品質確認

原画の品質と実行時のメモリは別に管理する。全24ステージの原画を一度に読み込まない。現在のステージに必要な人物と周辺区画を読み込み、画面外は描画を省く。遠くの人物は行動の更新頻度を落としても、時刻と目的を保持し、画面に戻ったときに停止した街にならないようにする。

原本をそのまま全てGPUへ置かない。既存の画像集約と重複フレームの共有を引き継ぎ、増えた素材はステージと周辺区画ごとに読む。必要な動作の切り出し、再生タイミング、画像集約、段階的な読み込みを使う。骨格制御への全面作り替えは必須にしない。参考として、128×128pxのRGBA画像は非圧縮で64KiB、10万コマなら約6.1GiBになる。これは計算上の原画サイズの例で、実際の使用量は圧縮・余白・読み込み範囲で変わる。

Godot 2Dのデスクトップ版を第一候補とする。スプライトとアニメーション制御を組み合わせられるが、導入するだけで大量人物が軽くなるとは見なさない。地域や階層で描画を分け、前後関係を維持して画像をまとめる。すべての人物を一つの大量描画グループへ押し込んで遮蔽や画面外省略を壊さない。

最初の性能目標は標準画面で60fpsを目指し、30fpsを下回る継続的な詰まりを解消すること。検証するMac・画面解像度・ズーム・人数・メモリを記録して判断する。現時点の計測結果や動作保証ではない。低画質化で人物の識別点を削る前に、読み込みと描画と行動計算を調整する。

| 審査 | 合格基準 |
| --- | --- |
| キャスト | 専用100人×24、共通枠、カメラマンの内数を照合。同一ステージに同じ見た目を出さない |
| 見分けやすさ | 通常表示・拡大・グレースケールの一覧で形の違いを確認。色だけで区別していない |
| 動作 | コマ間の顔・服・道具の変形、足滑り、瞬間移動、二重の持ち物を解消 |
| 場所 | 2階の床、階段、扉、手すり、カウンター、座席へ接地。相手と道具の受け渡しが一致 |
| 生活 | 歩行一辺倒ではなく、仕事・遊び・会話・休憩・乗車が起きる。集団の周期が揃わない |
| 視認性 | 対象が3秒以上重なって消え続けない。袋小路・入れない建物に永続的に逃げ込めない |
| 写真 | 初期0、1人1回、最大5、現像3秒、10％枠、撮影時点の記録、写真の中の対象だけの表示 |
| 対戦 | 相手の操作を写真で止めない。対象のみに付く目印がない。切断で両者を停止する |
| 全ステージ | 全24で開始人数、180秒、イベント、撮影、勝敗を実機確認。複数試行と長時間滞在で偏りも確認 |

## 13 台帳の使い方と未確定事項

付録には24ステージそれぞれの場所、19職種×5人＋カメラマン5人の配役、乗り物、小物、環境8セット、イベント6本を記載する。人物詳細台帳には最大4,300人の候補IDと外見案、主要役割、補助行動を収録する。共通枠への既存人物の割当を優先し、別の既存素材台帳に生成済み250ベースの原本・コマ・固定IDを保存する。役割付録は250種類を省略せず列挙する。素材台帳は背景の区画・建物・生活拠点・小物などの制作枠を個別に持つ。

後半のステージ名・広さ・人数、共通住民1,900人、動物96種、素材数、原画寸法、性能目標はこの文書での提案値。共通住民は既存232人を含む枠で、1,900人全員の新規生成を意味しない。実機と画面構成に合わせて増減するが、24ステージ、各専用100人、全体250役割、色違い廃止、初期撮影0回、カメラマン最大5人の条件を守る。

追加生成では既存原画を画風と縮尺の基準にし、まずステージに合う新ベースを同じ形式で増やす。設備との接地と巨大マップの2人用画面構成は並行して検証する。画像生成予算の追加確認を前提とした計画にはしない。制作期間は未見積もりで、検品にかかった実績から更新する。
