# 全24ステージ画像制作計画の資料

[画像とアニメーション制作計画](画像制作計画.html)をブラウザーで開くと、目次、ステージ別付録、人物検索、素材検索を読めます。HTMLには台帳を埋め込んでいるため、サーバーとネット接続は不要です。印刷は本文と付録を対象とし、全件の人物・素材台帳は検索画面とJSONで提供します。

- `IMPLEMENTATION_STATUS.md`：原画・ビルド・検証レポートから生成する現在の実装状況。
- `release-summary.json`：保存済み原画数・収録数・公開状態。
- `PLAN.md`：写真の新ルール、制作範囲、原画数量、品質基準、制作工程。
- `GENERATION_ESTIMATE.md`：現行ブラウザ形式で新規ベースを追加する基本シート数と、別途算定する役割差分・背景等。
- `EXISTING_FORMAT.md`：現在のコマ構成、再利用規則、生成済み250ベースの一覧。
- `existing-assets.json`：既存原本29シート・250ベースと7背景の台帳。
- `audit_existing_assets.py`：原本とメタデータを読んで既存素材を棚卸し。原本は変更しない。
- `generation-estimate.json`：同じ試算の計算結果。
- `estimate_generation.py`：素材台帳から生成回数を再計算。画像生成は実行しない。
- `CATALOG.md`：24ステージの配役・場所・環境・イベント、全250役割、全96動物。
- `production-ledger.json`：最大4,300人の配役候補と配置枠。共通枠には既存人物232人を優先し、動物18種は別に再利用する。
- `catalog_source.py`：ステージと役割の編集元。
- `build_catalog.py`：台帳と付録を生成し、人数・役割・IDの整合を確認。
- `build_reader.mjs`：本文・付録・台帳を読みやすいHTMLにまとめる。Node.jsとmarkedを使用。

既存画像を活かし、現行のコマ形式で新規画像も多数追加する方針です。その後の画像生成・実装を進めており、現在の状況は `IMPLEMENTATION_STATUS.md` に記録します。実装状況の更新はリポジトリ直下の `refresh_release_docs.py`、続いて `build_reader.mjs` を実行します。`--released` は全24ステージの検証とアプリ更新が揃った場合だけ指定できます。設計台帳や旧見積もりは、実際の収録名・採用枚数と区別して保存しています。
