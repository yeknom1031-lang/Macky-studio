# V5 検証記録

Godot 4.7.2 / macOS / Metal Mobile / アプリ1.4.0。

## 改善した点

1. 筐体の進行モニターを拡大し傾斜をつけた。不足色、次回×2、搬送中、残り払い出し、タワー製作／搬入、混雑による払出待機を表示する。結果の文字は80枠・BALL枠の特典も説明する。
2. 背景を暗くし、レバーの選択リング・角度目盛り・針を追加。狙いの予測線や発射力は追加せず、前→奥の重力レールを維持する。
3. UI上で指を離す・OSタッチキャンセル・フォーカス喪失・設定画面・同一レバーの複数指操作を修正。ボタンから大きく滑らせると連続投入を止める。小さい指の揺れでは止めない。
4. V4で残っていたJP時の画面全体への色被せを削除。盤面を隠さず筐体の照明で演出する。

## 自動検証

`tools/check.sh`：156項目成功。基本＋入力／表示75、物理抽選61、タワー13、90秒自然投入7。GUIより前の入力解放処理もテストするが、OS上の実タッチ操作の代替とはしない。

配布用V5アプリでも基本＋入力／表示75項目成功。`codesign --verify --deep --strict` でアドホック署名を検証。Apple公証やApp Store署名とは異なる。

新規28項目：左右同時押し、片側キャンセル、GUI上の解放、マウス解放、同一ボタン2指、微小移動、外側スライド、レバー単独所有、左右限界、選択表示、目盛り追従、フォーカス解除、ボタン復帰、モーダル解除と入力抑止、不足色、倍率保持、払出残数と更新、搬送表示、80とBALL特典、全画面フラッシュ非生成、JP入賞表示、表示時間の停止、結果→払出復帰、継続案内。

音素材・抽選確率・払い出し量・メダル物理・品質設定は変更していない。V4音テスト103項目は前版の結果であり、V5の新規実行数には加えていない。

## 描画の確認

V4とコンセプト画像を比較→進行モニターと手元目盛りを追加→実描画で目盛り板のレバー重なりを発見→位置を下げて再描画し確認。

キャプチャは実ゲームのMetalフレームバッファ。macOSが背景ウインドウの描画を抑制すると描画完了待ちが終わらなかったため、QAキャプチャ時だけRenderingServer.force_drawでフレームを要求するようにした。通常プレイのレンダリング設定は変更していない。[Godot公式API](https://docs.godotengine.org/en/stable/classes/class_renderingserver.html#class-renderingserver-method-force-draw)。このキャプチャ時のFPS表示は実機性能の評価には使わない。

`screenshots/v5-progress.png` は不足色と倍率をQAで設定した状態。自然プレイで獲得した証拠ではない。新規プレイの初期状態はCOLOR 0/3、倍率なし。

`screenshots/v5-jackpot.png` はIMPERIALの最終段JPをQAで発生させた配布アプリの描画。画面全体への色被せなしで、筐体表示・当選穴・外周照明を確認する。

## 残る制約

iPhoneでの署名・インストール・実タッチ・発熱・音の聞こえ方は未検証。完全版XcodeとApple Team IDが必要。自動操作テストの成功をiPhone実機確認と同一視しない。今回の画面操作ツールによる初回確認はタイムアウトし、直接操作は未確認のまま。

保存形式はV3互換。旧ビルドを残し、V5を `build/v5/MEDAL LOUNGE.app` と `build/MEDAL-LOUNGE-v5.zip` に書き出す。
