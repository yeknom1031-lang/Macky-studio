# V5 実装仕様

## 形状と操作

手前が+Z、奥が-Z、上が+Y。左右の開放投入レールは手前 `(±1.72,1.24,3.08)` から奥 `(可変X,0.62,-1.73)` へ下る。銀メダルの円盤面は垂直で、縁が溝に沿って転がる。角度変更時は転がり中のメダルもレールへ追従する。

レール内は拘束経路と移動距離／半径による回転。出口からはJolt剛体で上段へ落下する。砲台、発射力、見えない獲得誘導はない。上段は周期3.2秒・振幅0.36。下段へ届く押し出し面を持つ。下段は前縁Z=2.70まで。手前Z>2.67かつ左右幅内へ落ちたメダルを獲得し、横溝への落下は獲得しない。床は低摩擦の研磨面として設定する。

赤いMEDALボタンと黒いレバーは3D筐体に組み込む。投影位置で指／マウスを判定し、左右同時押しとレバー調整をポインターID別に処理。押下時の沈み込みと機械音あり。フォーカス喪失・モーダルで長押し状態を解除する。

## ポケット抽選と搬送

ROYALは赤・青・緑をリフトで回収し、3色そろった場合だけ5穴の抽選へ進む。収集途中は右側の保管カップと操作部のランプで表示。3色は抽選の参加条件であってJP確約ではない。

IMPERIALは外周／中周／内周の3トラック・各5穴。JPを突破すると同じ球を下側の返却経路→右側リフト→対応する内側ノズルへ運ぶ。各トラックは透明な円形ガードで区切られる。抽選球の半径は全段で同じ。

抽選床は穴の境界を含む三角形メッシュを生成し、穴内部の三角形を除いた実体コリジョン。最初の2.2秒は各穴の物理蓋が球を支え、0.35秒かけて開く。球が床より下へ落ち、対応穴の範囲内に入った時だけ結果を確定する。タイマーで賞を割り当てない。浅い軌道の代用として弱い半径方向の力を加え、長時間停滞時には弱い接線方向の振動を加える。特定の賞へ向ける力ではない。脱落時は同じ抽選を再投入し、賞を与えない。

回収／リフト／ノズル内は経路アニメーション、皿上は自由剛体。盤面の大きな景品球と内部搬送・抽選の球は可読性優先で縮尺が異なる。実機を計測して再現した機構ではなく、購入・換金のないゲームの近似モデル。現在の5賞は20／40／80枚・BALL・JP。ROYALの80枠は次の抽選だけ払出2倍の権利も与え、JP・BALLの枚数にも適用する。倍率は1回で消費し、保存・復元に含む。

## タワーと払い出し

中央36段×7枚、左右22段×1枚。銀メダル296枚を省略せず個別に描画する。安静積層は合計質量を持つ円柱の集約剛体で接触・移動・傾斜を計算し、水平速度・落下速度・傾きが閾値を超えると全構成メダルを独立剛体へ戻す。固定した飾りではない。積層途中の状態とメンバー対応を保存・復元する。

積み上げ装置では1枚ずつ7列の層を作る。可動パレットで持ち上げ→前方へ搬送→下降し、盤面上のタワーへ切り替える。搬送中だけは固定軌道。払い出しホッパーは実際の傾斜シュートから銀メダルを落とし、直接カウンターへ賞を足さない。

## 描画と負荷

Godot Mobile / Metal。生成した背景を背面Canvasへ、金属表面を材質へ、銀メダル刻印をシェーダーへ、装飾パネルを筐体へ適用。別途生成したパノラマを反射環境に使用する。PNGは元解像度を保持。材質はミップマップと異方性フィルターを使用。

メダルは64分割・面取り付き。面と縁の法線を分離し、刻印はテクスチャーと微細な法線変化で表現。MultiMeshで全枚を共有描画し、静止中の更新を省略。筐体の面取り形状、クローム、ガラス、真鍮、発光、4灯（2灯に影）を使用。パストレーシングやスクリーンスペース反射は使用しない。

90HzのJolt物理、4x/8x MSAA、影のアトラス4096、描画解像度を維持。積層の集約と休止・描画共有を最適化に使う。衝突計算の許容侵入量0.001、速度反復10、位置反復2。反復数を32/8に上げる案はCPU負荷増と積層不安定が残るため不採用。集約方式の導入後は12/4の追加反復も外し、標準反復数で回帰検証した。設定の意味は[Godot ProjectSettings](https://docs.godotengine.org/en/4.6/classes/class_projectsettings.html)で確認した。

財布・補充待ち・850枚上限はない。手動投入は盤面枚数によらず受け付ける。共有描画容量は256枚単位で拡張、回収済み剛体を再利用。自動払い出し・積み上げだけは密度1200枚で待機し、予約を保持して再開する。同時レール走行14枚、盤面球7個。無制限プレイは端末メモリー／性能まで無制限にするものではない。

## 保存・端末

JSONを一時ファイルへflush、前回をバックアップしてrename。台ごとに独立保存。終了・中断・台切替・12秒ごとに保存。新規プレイは現行データを日時付きアーカイブへ保管してから初期化する。音量／画質／触覚／ガイド既読は維持。保存失敗時は新規開始しない。

V3保存はV2/V1と別ファイル。旧データの下段Z座標を新しい奥行きへ拡張して読み込む。中断抽選は再抽選、製作中タワーは残り素材へ戻して再製作する。完全なフレーム単位リプレイではない。

540×1080基準の縦画面。日本語UIとシステムフォント、iOS安全領域対応コードあり。ただしiPhone署名・インストール・実測は未完了。通信・課金・広告・分析SDK・カメラ・マイク取得なし。音は66個のCC0音素材とオリジナル合成PCM。

## V4 音と抽選演出

近距離24声、遠方8声、ファンファーレ専用4声を起動時に生成し再利用する。環境・BGM・転がり・緊張感用のループは固定。遠方だけローパスと残響を使い、左右に配置。素材選択は直前との重複を避け、非音楽系に軽いピッチ変動を加える。ゲーム全体のバスに-1.5dBのピークリミッターを置く。音量設定は従来の3系統を維持。

抽選中はBGMを32%、環境音を60%へ滑らかに下げる。球の速度・角度からクリック音の間隔と左右を決め、穴の開放時刻に一度だけ合図を出す。通常当選・次段階・JPを別素材で表現し、結果後も3秒／6秒は背景を抑える。モーダルで抽選ループとファンファーレを停止状態へ、台切替ではキャンセルする。

抽選器の外周ランプは一つのシェーダーで走る光を描く。筐体内表示と当選穴のリングを連動し、結果時は緩やかな発光変化。抽選中のカメラ画角は40度から39.3度へわずかに寄る。確率・穴の物理判定・払い出しルールはV3と同じ。V3保存をそのまま使用する。

## V5 操作と表示

指・マウスの解放はGUIが消費する前の `_input` で所有状態を解除する。押し始めは従来どおり `_unhandled_input` で処理し、UIへの操作をメダル投入に流用しない。ボタンの初期判定は画面幅の6.6%、スライド解除は10%とし、小さな指の揺れを許容。同一レバーには1つのポインターだけが角度変更の所有権を持つ。設定・中断・フォーカス喪失は所有状態と物理ボタンの見た目を同時に戻す。

選択レバーに発光リングを置き、黒い目盛り板と金属の針で角度を表示する。目盛りは共有描画。予測軌道や発射力調整ではない。筐体内表示を拡大して傾け、結果の後は実際の払い出し残数→製作／搬送→不足色／段階の順で表示する。文字は最大5Hz・変更時のみ更新。旧JPの全画面ColorRectは廃止した。
