# 実装仕様

## 重要な形状と座標

手前が+Z、奥が-Z、上が+Y。投入レールは手前 `(±1.72, 1.24, 2.08)` から奥 `(可変X, 0.62, -1.73)` へ下る開放溝です。円盤の面は垂直、縁が溝に接触している状態を描画します。角度変更時は転がり中のメダルもレールへ追従します。

レール上だけは拘束経路と距離に応じた回転で安定させ、出口でJolt剛体へ引き継ぎます。上段、落下、下段、積層タワーは剛体です。見えない力でユーザーのメダルを当たりへ移動する処理はありません。

上段の棚は周期3.2秒、前後振幅0.36。床面だけでなく下段へ届く押し出し面を持ちます。後方の固定壁は棚の全ストロークと重なり、奥にコインが抜けるすき間を作りません。

## 抽選と搬送

ボールの回収とリフト搬送は経路アニメーション。ルーレット上では実際の剛体球が外周壁・区切りと衝突し、静止または7秒後の位置から5区画を判定します。浅い皿の傾斜に相当する弱い外向き力を与えます。完全な実機測定モデルや認証された公平な乱数抽選ではなく、購入・換金のないゲーム内演出です。

タワー機の3段階は同じ抽選器で順番に抽選し、表示灯で進行を示します。物理的に3個のルーレットがある構成ではありません。

払い出しホッパーは横へ移動しながら盤面へメダルを落とします。タワーは可視の組み立て位置で積み、搬入・下降して剛体に切り替えます。

## 描画と負荷

Godot Mobile / Metal、独自の金属シェーダー、共有メッシュ・材質、環境反射、スポットライトの影、ガラス、発光。スクリーンスペース反射やパストレーシングは使用していません。

盤面850枚の上限と財布による投入制限は撤去。手動投入は盤面枚数によらず受け付けます。回収済み剛体を再利用し、共有MultiMeshは256枚単位で容量を拡張。自動の払い出し・タワー生成だけは盤面密度1200枚以上で一時停止し、手動レールの投入余地を優先します。払出予約は消えず、密度が下がると続行。物理的に同時に転がるレール上のメダルは最大14枚、盤面ボールは最大7個です。無制限プレイは無制限の端末メモリーや処理性能を意味しません。

64分割の面取りメッシュと各コインの剛体は維持。メダル描画をMultiMeshで統合し、休止中の姿勢更新は省略。静的筐体も材質と共有形状で統合します。接触音は全剛体の個別シグナル監視から分散サンプリングへ変更。物理90Hzを維持し、描画補間で移動を滑らかにします。レール角度変更は既存形状の変形のみでノードを作り直しません。60Hz物理も試しましたが、積層タワーの安定性を優先して採用していません。

画像生成した背景PNGを背面Canvasへ、ステンレスPNGを金属材質へ、銀メダルPNGをコインシェーダーへ適用。材質テクスチャーはミップマップと異方性フィルターを使用します。物理モデルを背景画像へ置き換える実装ではありません。

UIは540×1080を基準に拡張し、iOSの安全領域を考慮。操作UIは日本語。Mac/iOSのシステムフォントを使用します。

投入・狙い操作は筐体上の3Dボタンと黒いレバーの画面投影位置でヒット判定。ポインターIDごとに追跡し、左右同時押しとレバー操作を扱います。ボタンは押下時に沈みます。画面上のスライダーと財布パネルは廃止。フォーカス喪失・モーダル表示時に押下状態を解除します。

## 永続化と終了

JSONを一時ファイルへ書いてflushし、前回ファイルをバックアップ後にrenameします。各台は独立して保存。旧残高フィールドは互換性のため残しますが投入可否には使いません。中断した抽選を待機キューへ戻すため、抽選途中に終了しても獲得ボールは消えません。

V2は旧V1保存を初回に読み取り、新しいV2ファイルへ保存します。新規ゲーム時は現行保存を日時付きアーカイブへコピーしてから盤面・獲得数・投入回数・JP回数をリセット。音量・画質・触覚・ガイド既読は維持。保存失敗時は新規ゲームを開始しません。

通信、課金、広告、分析SDK、カメラ、マイク取得は実装していません。音声は実行時の合成PCMです。GodotランタイムのライセンスはGodot公式のMITライセンスに従います。
