# 描画負荷比較 — V1 → V2

## 条件

2026-09-22、Apple M2、Godot 4.7.2、Metal Forward Mobile。両版とも540×1080、4x MSAA、元の64分割メダル、同じ影設定、90Hz物理。V1はコミット `048fa95` の別コピー。V2は今回の変更。VSync有効。

`tools/benchmark.gd` を両版へ同一内容で適用。IMPERIAL TOWER、払い出し180枚、150フレームのウォームアップ後に600フレーム測定。12フレームごとに左投入。別々に実行して描画アプリ同士の競合を避けました。異なる物理結果のため最終盤面枚数は厳密には一致しません。

## 結果

| 測定項目 | V1 | V2 |
|---|---:|---:|
| 最終盤面のメダル数 | 588 | 594 |
| 描画コマンド数／フレーム | 1,445 | 181 |
| 描画オブジェクト数 | 1,571 | 186 |
| ノード数 | 2,092 | 1,517 |
| 描画プリミティブ数 | 2,119,238 | 2,214,572 |
| process時間 中央値 | 13.611 ms | 13.886 ms |
| process時間 95パーセンタイル | 16.958 ms | 15.416 ms |
| 600フレームの実時間 | 10,002.735 ms | 10,001.141 ms |

描画コマンドは**約87.5%減少**。形状を削減した数値ではなく、MultiMeshと静的筐体のバッチ化によるものです。生成材質や筐体の追加によりプリミティブ数はむしろ増えています。

この測定では両方とも約60fps上限に到達しています。中央値のprocess時間は改善していません。95パーセンタイルは約9%短縮しましたが、単一Mac上の観測であり持続的な速度向上を保証しません。物理モニターは中央値5.371→4.650 ms、95パーセンタイル6.090→25.019 msとばらつき、物理負荷が改善したとは判断していません。軽量化の確かな成果は描画コマンド・オブジェクト数の削減です。

## 品質を保った変更

- コインの個別描画ノードを共有MultiMeshへ統合。面取り、面テクスチャー、剛体、影は維持。
- 動かないメダルの表示姿勢更新を省略。回収済み剛体を再利用。
- 静的筐体を材質・形状ごとにまとめて描画。
- レール角度変更で形状を毎回作り直す処理を撤去。
- 接触音を分散サンプリング。全剛体の個別接触シグナル登録を撤去。
- テクスチャーにミップマップと異方性フィルターを使用。
- 描画解像度、MSAA、動的影、64分割形状、90Hz物理を維持。60Hz物理の試行はタワーの安定性のため不採用。

## 再現

```sh
godot --path . --resolution 540x1080 --fixed-fps 60 --script res://tools/benchmark.gd
```

`--fixed-fps 60` はベンチマークの進行条件であり、90Hzの物理更新設定とは別です。通常起動には付けません。描画なしのヘッドレス試験ではGPU性能を測れません。

iPhone上の実fps、発熱、メモリー上限、長時間負荷はまだ実測していません。無制限投入は端末性能まで無限にするものではありません。
